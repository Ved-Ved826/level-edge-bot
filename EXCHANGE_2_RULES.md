## 1. Контекст текущей системы

- Файлы биржи: `worker/src/commands/{company,stocks,invest,divest,portfolio}.ts`, `worker/src/worker.ts` (маршрутизация), `worker/src/db/queries.ts` (хелперов биржи нет), `collector/src/collector.ts` (регистрация команд, фоновые таймеры, схема БД, `processDailyCompanyGrowth`, `liquidateCompaniesOnSeasonChange`).
- Модель: у компании 100 акций (51 основателю, 49 в `available_shares`). `circulating = 100 - available_shares`. `NAV = treasury / circulating`. Стартовая казна 500.
- Сейчас: покупка `+6%` к базе (3% основателю, остаток в резерв), продажа `-5%` (в резерв). Сделки цену не двигают, рост даёт только суточный грант из `server_reserve` (`min(floor(1% казны), 100, reserve)`).
- `server_reserve` — общий банк гильдии: пополняется комиссиями и взносом за создание компании, финансирует суточный рост. Не обнуляется при смене сезона.
- Конец сезона: `payout = floor(shares * treasury / circulating)`, остаток в резерв, затем удаляются `company_crises`, `company_shares`, `companies`.
- БД: LibSQL/Turso. Интерактивные транзакции могут быть недоступны (в гайде есть противоречие: `db.transaction("write")` в company.ts против замечания про `@libsql/client/web`). Проверь, какой клиент реально используется, и работай в его пределах.

## 2. Незыблемые инварианты

1. **Сохранение монет.** В каждой операции сумма изменений всех балансов (игроки + казны компаний + `server_reserve`) равна нулю. Монеты не создаются и не исчезают. Рост казны и плюсы кризисов берутся из `server_reserve`, минусы кризисов уходят в него.
2. **Только целочисленные деньги.** Никакого float в итоговых суммах. Проценты хранить и считать в bps (1 bps = 0.01%). Округление в пользу системы: покупателю `ceil`, продавцу `floor`. Формулы `ceil(a*b/c) = floor((a*b + c - 1) / c)`.
3. `treasury >= 0` всегда, а при активной торговле `>= 1`. Никогда не делить на `circulating <= 0`.
4. **Атомарность.** Одна логическая операция = один `db.batch`. Каждый следующий statement в батче должен быть защищён условием успеха первого (guard), не слабее, чем в текущем `invest.ts`/`divest.ts`. Проверка «состояние не изменилось с момента расчёта» обязательна (treasury, available_shares, mood_bps, mood_updated_at).
5. **Идемпотентность фоновых задач.** Повторный запуск любой задачи ничего не дублирует (маркер/статус + условный UPDATE).
6. **Побочные эффекты после коммита.** Ответ пользователю и сообщения в канал отправляются после успешного коммита. Сообщения в Discord идут через outbox-таблицу `market_events`, а не напрямую из обработчиков, чтобы сбой Discord не ломал сделку.
7. Пользовательский текст (name, description) проходит `sanitizeText`. В сообщениях бота `allowed_mentions` только для явно нужных пользователей (например, владелец кризиса). Никаких массовых упоминаний.
8. **Обратная совместимость.** Миграции идемпотентны (`CREATE TABLE IF NOT EXISTS`; для `ALTER TABLE ADD COLUMN` сначала `PRAGMA table_info`). Существующие компании и акции продолжают работать без ручных действий.
9. Все тюнинг-константы живут в одном модуле (`worker/src/exchange/constants.ts`). Если collector не может импортировать из worker, продублируй минимально нужные константы с комментарием `// keep in sync with worker/src/exchange/constants.ts`.
10. Не добавляй новых зависимостей без необходимости. Если добавляешь (например, тест-раннер), скажи об этом отдельной строкой в конце ответа с командой установки.
11. Комментарии в коде на русском (как в остальной кодовой базе), к каждой новой формуле объясняй, почему она такая.

## 3. Принятые дизайн-решения

### Настроение (mood)
- Хранится как `mood_bps INTEGER` в `[-2500, +2500]` и `mood_updated_at INTEGER` (unix, секунды) в `companies`.
- Затухание **ленивое**: эффективное настроение считается при чтении, `mood * 0.5^(часы / MOOD_HALF_LIFE_HOURS)` с усечением к нулю. Cron не нужен.
- **Асимметричная надбавка, остающаяся в казне:**
  - `mood > 0` (ажиотаж): покупатель доплачивает премию `base * mood`, она идёт **в казну** (растит NAV держателей). Продавец получает не больше NAV.
  - `mood < 0` (паника): продавец получает `NAV * (1 + mood)`, разница **остаётся в казне** (достаётся оставшимся держателям). Покупатель платит NAV.
  - Казна **никогда** не платит продавцу больше NAV.
- Сдвиг настроения от сделки пропорционален доле сделки в обращении (`k / circulating`), не фиксирован за операцию. Нарезка на мелкие сделки не даёт преимущества.

### Кризисы
- Спавнит collector. Владелец выбирает одну из 2–3 **кнопок** с заранее заданным профилем риска, без свободного текста и без ИИ-оценки.
- Дельта считается в процентах казны, с ограничениями. Плюс берётся из резерва, минус уходит в резерв.
- Молчание владельца до дедлайна (24 часа) даёт **худший** исход (всегда хуже среднего исхода любой кнопки).

### Публичность
- Лента: «киты», резкие движения, кризисы, ежедневная сводка топ-5 роста/падения, итоги сезона. Всё через outbox `market_events`.

### Сезонный рейтинг
- Рейтинг инвесторов по ROI за сезон, лучшая компания по итоговому NAV. Результаты пишутся в той же атомарной операции, что и ликвидация, до удаления данных.

### Осознанно НЕ делаем
- **Сплит акций:** в NAV-модели денег не создаёт, а порог «circulating >= 200» невыполним при 100 акциях. Порог NAV >= 500 недостижим при потолке роста 100 🪙/день. Не реализовывать.
- Оценка кризисов через LLM и свободный текст-ответ владельца.
- Цена продажи выше NAV за счёт казны (см. асимметричное настроение; цена выше NAV возможна только через P2P, где платит покупатель).

## 4. Константы по умолчанию (`constants.ts`)

| Константа | Значение | Смысл |
|---|---|---|
| `TOTAL_SHARES` | 100 | как сейчас |
| `BUY_FOUNDER_BPS` | 200 | роялти основателю с базы покупки |
| `BUY_RESERVE_BPS` | 200 | в резерв с базы покупки |
| `SELL_RESERVE_BPS` | 300 | в резерв с выплаты |
| `MOOD_MAX_BPS` | 2500 | коридор настроения ±25% |
| `MOOD_IMPULSE_BPS` | 1500 | сдвиг за сделку на всю обращающуюся долю |
| `MOOD_MAX_SHIFT_PER_TRADE_BPS` | 1000 | потолок сдвига за одну сделку |
| `MOOD_HALF_LIFE_HOURS` | 18 | период полураспада настроения |
| `WHALE_MIN_SHARES` | 5 | порог «кита» по акциям |
| `WHALE_MIN_COINS` | 1000 | порог «кита» по базе сделки |
| `CRISIS_MIN_TREASURY` | 300 | минимум казны для кризиса |
| `CRISIS_MIN_INTERVAL_HOURS` / `MAX` | 6 / 8 | интервал спавна по гильдии |
| `CRISIS_COMPANY_COOLDOWN_HOURS` | 48 | пауза между кризисами одной компании |
| `CRISIS_TTL_HOURS` | 24 | время на решение |
| `CRISIS_MAX_LOSS_BPS` | 2500 | потолок потери за кризис |
| `CRISIS_MAX_GAIN_BPS` | 1500 | потолок прибыли за кризис |
| `CRISIS_MAX_GAIN_COINS` | 1500 | потолок прибыли в монетах |
| `CRISIS_LOSS_MOOD_FACTOR` | 1.5 | усиление паники при потере (в bps считать целыми) |
| `ROI_MIN_INVESTED` | 500 | минимальный объём для рейтинга ROI |

Комиссии 4%/3% ниже прежних 6%/5%, потому что настроение добавляет динамическую стоимость. Следи за балансом резерва: если он падает, комиссии можно поднять одной константой.
