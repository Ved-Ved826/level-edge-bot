      - client.login() (3366) без .catch: невалидный токен (code 4004) ->

      - client.on('ready') (2961) вместо once: после re-identify (invalid

        стартуют ВТОРОЙ раз -> двойные таймеры (двойные спавны/начисления).

        участнику каждой гильдии — при латентности Turso ~100-300мс и сотнях
        участников хвост цикла превышает интервал 5 мин -> наложение прогонов
        (setInterval не ждёт async; guard-флага «уже идёт» нет).
      - Healthcheck всегда 200 (5-14), даже если Gateway мёртв; у .listen()
        нет обработчика error (EADDRINUSE будет глотаться глобальным
        uncaughtException-хендлером).
      - uncaughtException глотает и НЕ-сетевые ошибки (34-48) — процесс может
        жить в неизвестном состоянии.
      - collector.ts:1693-1694 и 778-779: подсчёт закрытых квестов для стрика
        БЕЗ фильтра по дате (completed_at IS NOT NULL за всё время) — после
        первого закрытого квеста «сегодняшних» квестов достаточно навсегда;
        стрик может никогда не сброситься.
      - collector.ts:479: new Date('YYYY-MM-DD') парсится как UTC-полночь, а
        не полночь Владивостока -> граница дня witcher_gwent сдвинута на 10ч.
      - collector.ts:1612-1623: getWeekKey считает Math.ceil(dayOfYear/7), это
        не ISO-неделя; week_key в weekly_activity может не совпасть с расчётом
        воркера.
      - Fallback DATABASE_URL = 'libsql://localhost' (813) — при запуске не из
        папки collector (dotenv читает cwd/.env) бот молча падает в бесконечные
        ENOTFOUND, которые глотаются глобальными обработчиками. Запускать
        `npm run start -w collector` (cwd = collector/), что и делает setup-termux.sh.
