Задача: превратить сезон в гонку: рейтинг инвесторов по ROI и лучшая компания сезона. Данные для этого — таблица company_trades (шаг 3).

1. Таблица (идемпотентная миграция): season_results (id, guild_id, season_id, kind TEXT CHECK(kind IN ('investor','company')), subject_id TEXT (user_id или company_id), label TEXT (имя/тикер на момент итогов), invested INTEGER, returned INTEGER, roi_bps INTEGER, rank INTEGER, created_at INTEGER). Индекс (guild_id, season_id, kind, rank).

2. Расчёт ROI игрока за сезон (чистая функция + тест):
   invested = сумма coins по buy из company_trades сезона + стоимость создания компании, если он основатель;
   returned = сумма coins по sell + выплаты дивидендов при ликвидации + полученные роялти основателя;
   roi_bps = trunc((returned - invested) * 10000 / invested), только для invested >= ROI_MIN_INVESTED.
   Если чего-то из этого нельзя получить из имеющихся данных (например, роялти не записаны в company_trades), НЕ выдумывай: сформулируй упрощённое определение по данным, которые реально есть, и опиши его комментарием и в документации.
   Компании ранжируются по итоговому NAV (выплата на одну обращающуюся акцию при ликвидации).

3. Ликвидация. В liquidateCompaniesOnSeasonChange перед удалением компаний посчитай результаты гильдии, запиши season_results и событие 'season_results' (топ-3 инвесторов и топ-3 компаний) В ТОМ ЖЕ атомарном батче, что и выплаты. Существующие гарантии (маркер last_season_reset обновляется строго после успешного коммита, ошибка в одной гильдии не прерывает остальные, первый запуск без ликвидации) должны сохраниться полностью. company_trades и company_nav_history при ликвидации не удалять.

4. Команда `/exchange-top` (публичная): текущий рейтинг сезона в реальном времени (оценка открытых позиций по «выходу сейчас», как в /portfolio) + итоги прошлого сезона из season_results. Зарегистрируй в collector.

5. Роли победителям и награды НЕ реализуй. Оставь в отправителе событий TODO-комментарий с описанием, какие данные для этого уже есть в season_results.

6. Учти в тексте объявления и в документации: в первом сезоне после внедрения история сделок может быть неполной, поэтому рейтинг считается только по сделкам, записанным после обновления.

Критерий готовности: тесты формул ROI зелёные; симуляция смены сезона на тестовой БД записывает season_results и объявляет топ-3; повторный запуск ликвидации не дублирует записи.
