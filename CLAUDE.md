## Что это
Ультрабыстрый, стильный серверный трекер активности, уровней и соревновательных механик:
1. **Edge-архитектура Cloudflare Workers** для мгновенных ответов на слэш-команды (<300 мс) без задержек и очередей.
2. **Дизайнерские PNG-карточки** через Satori + WASM (тёмная тема Discord, аватарка, статус-кольцо, неоновый градиент, расчёт оставшегося XP).
3. **0 рублей затрат** — бесплатные лимиты Cloudflare Workers, Turso (libSQL) и контейнер на Render.
4. **Геймификация:** ежедневные квесты, детальная статистика за день (`/rank-today`), еженедельные кубки, 4 сезона в год с вайпами и итоговый ежегодный «Server King» (Spotify Wrapped для Discord).

## Архитектура системы

### 1. Collector Daemon (`/collector`, Node.js в Docker на Render)
- Держит постоянный WebSocket Gateway с Discord.
- Отвечает за непрерывный сбор данных: антиспам-кулдаун на сообщения (30 сек), сегментный учёт войса (без накрутки при заглушении `selfDeaf + selfMute`).
- Ведёт посуточный учёт активности (`user_daily_activity`) и трекает прогресс дейли-квестов.
- Имеет встроенный HTTP Healthcheck-сервер на порту 10000 для Render.
- **НЕ** рендерит картинки и **НЕ** отвечает на слэш-команды.

### 2. Cloudflare Worker (`/worker`, TypeScript Edge Worker)
- Принимает HTTP Interactions Endpoint от Discord (Ed25519 верификация подписи).
- Моментальный ответ `type: 5` (DEFERRED) + асинхронный фоновый рендер через `ctx.waitUntil(...)`.
- Рендерит карточки через Satori (JSX → SVG) и `@resvg/resvg-wasm` (SVG → PNG) с кэшированием `wasmInitPromise`.
- Отвечает на слэш-команды (`/rank`, `/rank-today`, `/leaderboard`, `/quests`) и обрабатывает клики по кнопкам (`type: 7` UPDATE_MESSAGE).

### 3. Serverless DB (Turso / libSQL)
- Единая база данных, доступная по HTTP API обоим сервисам.

## ТЕКУЩИЕ И БУДУЩИЕ ЭТАПЫ

### Этап 1 — Ежедневные квесты и активность за сегодня (/rank-today, /quests)

#### 1.1. Посуточный учёт активности:
- Таблица `user_daily_activity`:
  `user_id TEXT, guild_id TEXT, activity_date TEXT, messages_count INTEGER DEFAULT 0, voice_seconds INTEGER DEFAULT 0, PRIMARY KEY(user_id, guild_id, activity_date)`
  (где `activity_date` — дата в формате `YYYY-MM-DD` по UTC).
- В `collector`: при каждом сообщении и при закрытии отрезка войса делать UPSERT в `user_daily_activity`.

#### 1.2. Команда `/rank-today`:
- Выводит стильный эмбед (Blurple 0x5865F2) с итогами дня пользователя:
  - 💬 Сообщений сегодня: **N**
  - 🎙 В войсе сегодня: **M мин.** (X ч. Y мин.)
  - 🎯 Выполнено квестов за день: **K / Total**
  - 📈 Получено XP за день
  - Футер: `Дата: YYYY-MM-DD • Сброс в 00:00 UTC`

#### 1.3. Огромный пул квестов (`quests_pool`):
В базе создаётся пул из 15+ разнообразных квестов:
- *Текстовые:* «Разминка пальцев» (10 сообщ / 50 XP), «Активный спикер» (30 сообщ / 150 XP), «Гроза чата» (60 сообщ / 300 XP), «Стена текста» (100 сообщ / 500 XP), «Философ» (сообщения длиннее 100 символов).
- *Голосовые:* «Заглянул на огонек» (15 мин / 100 XP), «Душевный разговор» (45 мин / 250 XP), «Войс-марафон» (90 мин / 450 XP), «Хозяин эфира» (150 мин / 750 XP).
- *Ситуативные / Время суток:* «Утренний кофе» (сообщения с 06:00 до 12:00), «Ночной дозор» (войс после полуночи), «Счастливые часы» (активность во время пикового онлайна).
- *Комбо:* «Двойной удар» (25 сообщений + 25 минут в войсе).

#### 1.4. Ротация квестов и команда `/quests`:
- Таблицы: `quests_daily` (квесты дня для гильдии) и `user_quest_progress` (прогресс юзера).
- В 00:00 UTC (или при первом запросе за день) гильдии назначаются 3-4 случайных квеста из пула (1 текстовый, 1 голосовой, 1 особый/сложный).
- В `collector`: автоматический инкремент прогресса квестов при действиях, начисление `reward_xp` при достижении цели и пометка `completed_at`.
- В `worker`: команда `/quests` выводит список дейликов с текстовыми прогресс-барами вида `[████░░░░] 4/10` или `✅ Выполнено (+250 XP)`.

### Этап 2 — Еженедельные лидеры и Сезонные Лиги (Вайпы 4 раза в год)

#### 2.1. Еженедельный спринт («Лидер недели»):
- Таблица `weekly_activity` (user_id, guild_id, week_number, year, xp_earned).
- Автоматический сброс в ночь с воскресенья на понедельник (00:00 UTC).
- Награждение топ-3 недели: выдача временной роли «Чемпион недели» (назначается ботом в collector) и бонусный несгораемый престиж-XP.

#### 2.2. Сезонные лиги (Весна / Лето / Осень / Зима):
- Разделение опыта в таблице `users`: `total_xp` (вечный опыт аккаунта) и `season_xp` (опыт текущего сезона).
- Четыре сезона:
  - 🌸 **Весенний кубок** (1 марта — 31 мая)
  - ☀️ **Летний драйв** (1 июня — 31 августа)
  - 🍂 **Осенний марафон** (1 сентября — 30 ноября)
  - ❄️ **Зимняя битва** (1 декабря — 28/29 февраля)
- В конце каждого сезона:
  - Автоматический снапшот топа сезона в таблицу `season_archive`.
  - Выдача памятных сезонных значков/бейджей призёрам.
  - Вайп `season_xp = 0` у всех участников гильдии.
- В `/leaderboard` добавляются кнопки-переключатели: `[Текущий сезон]` и `[За всё время]`.

### Этап 3 — Годовые номинации «[Server_Name] KING / RECAP» (Discord Wrapped)

Ежегодное грандиозное подведение итогов 31 декабря в 18:00 UTC:
- Генерация годового интерактивного дайджеста в системный канал сервера.
- Номинации и коронация:
  - 👑 **Chat King** — пользователь, отправивший больше всего сообщений за год.
  - 🎙 **Voice King** — пользователь с наибольшим количеством часов в войсе за год.
  - 🦉 **Night Owl (Ночной сыч)** — рекордсмен по активности между 01:00 и 06:00.
  - ⚡ **Iron Butt (Марафонец года)** — самая длинная непрерывная войс-сессия за всю историю сервера без единого дисконнекта.
  - 🎯 **Quest Master** — закрыл больше всего ежедневных квестов за год.
- Персональная команда `/recap` (доступна в декабре/январе) — личная статистика пользователя: его личный топ-день, суммарные часы, любимый голосовой канал и место среди всех участников.

### Этап 4 — Система престижа (Prestige & Stars)
- Максимальный уровень `MAX_LEVEL = 100`.
- По достижении 100 уровня на карточке `/rank` появляется интерактивная кнопка **«Престиж»**.
- Сброс уровня в 0 с сохранением звезды престижа: `prestige_count += 1`.
- Отображение звёзд на PNG-карточке `Card.tsx` (например, `★ x1`).

---

### Этап 5 — CSV-экспорт для владельцев и администраторов
- Команда `/export` (только для участников с правами `ADMINISTRATOR`).
- Выгрузка полной аналитики сервера: `user_id`, ник, `total_xp`, `season_xp`, `messages_count`, `voice_seconds`, `prestige_count`.
- Отправка компактного CSV-файла прямо в чат (или в Cloudflare R2 при гигантских объемах).
- Защита от спама: не чаще 1 раза в 10 минут на сервер.

## ⚠️ КРИТИЧЕСКИЕ ПРАВИЛА ДЛЯ ОКРУЖЕНИЯ WINDOWS И ПРОЦЕССОВ

### 1. БЕЗОПАСНОСТЬ ЛОКАЛЬНОГО ШЛЮЗА OMNIROUTE (ПОРТ 20128)
- **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** выполнять массовое убийство процессов: `taskkill /F /IM node.exe`, `killall node` и аналоги!
- На машине запущен локальный AI-шлюз **Omniroute** на порту `20128` (процесс Node.js), через который идут все запросы модели. Убийство `node.exe` моментально уничтожает API-соединение с ошибкой `ConnectionRefused`.
- Для остановки зависших процессов разработки (например, wrangler на 8787):
  1. Найти точный PID: `netstat -ano | findstr :8787`
  2. Завершить ТОЛЬКО этот PID: `taskkill /PID <PID> /F`

### 2. РАБОТА С ФАЙЛАМИ В WINDOWS
- **НИКОГДА** не используй незакавыченный `cat << EOF` в bash/sh оболочке: конструкции `${var}` воспринимаются как переменные bash и стираются, ломая TypeScript/JSX код.
- При полной перезаписи файлов следи за тем, чтобы инструмент не склеивал старый и новый код (проверяй количество строк через `wc -l` или `git diff`).
- Чистая безопасная запись при необходимости:
  `node -e "fs.writeFileSync('путь', Buffer.from('...', 'utf-8'))"`

### 3. ПРЕДОТВРАЩЕНИЕ БЕСКОНЕЧНЫХ ЦИКЛОВ ПРАВОК
- Если после компиляции линтер сообщает об ошибках: **ОСТАНОВИСЬ**. Проверь целостность файла, а не запускай 10 слепых микро-редактирований подряд.
