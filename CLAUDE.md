Это не техническая задача, а контекст. Сохрани текст ниже как `CLAUDE.md` в корне

```
# LevelEdge — Discord-бот учёта активности

## Язык общения

Всегда отвечай и объясняй свои действия по-русски, независимо от того, на каком
языке написаны названия переменных, комментарии в коде или сообщения об ошибках
в логах — это нормально, что код на английском, но объяснения, вопросы и статус
выполнения задачи — только на русском.

## Что это

Ультрабыстрый, стильный серверный трекер активности и уровней нового поколения.
Решает две главные боли классических ботов вроде MEE6 или ProBot:

1. Не тормозит и не падает при наплыве запросов — благодаря Edge-архитектуре
   Cloudflare (обработка размазана по 300+ дата-центрам, а не идёт через один сервер).
2. Стоит 0 рублей в обслуживании, при этом выглядит как дорогой кастомный продукт
   с красивой графикой — карточки в стиле тёмной темы Discord, а не унылые
   текстовые эмбеды.

## Как это видит обычный пользователь

- Пассивная жизнь: человек сидит на сервере, общается в текстовых каналах,
  играет с друзьями в войсе. Никаких команд для старта — бот молча ведёт учёт.
- /rank (или /rank @username) — за 250–350 мс бот выкатывает дизайнерскую
  PNG-карточку: аватарка с цветным кольцом статуса, уровень и позиция в топе
  ("#4 из 1500"), неоновый прогресс-бар XP, две плашки-счётчика
  (💬 сообщений / 🎙 часов в войсе).
- /leaderboard — интерактивное меню с кнопками ("Топ по сообщениям",
  "Топ по войсу") и пагинацией [◀] [▶].

## Архитектура — два независимых сервиса + общая БД

Собственно микросервисы общаются не напрямую друг с другом, а только через
общую бессерверную базу данных. Это ключевое архитектурное решение проекта,
не отступай от него без явной причины.

1. **Collector Daemon** (`/collector`, Node.js/Bun) — живёт на бесплатном
   микро-контейнере (Fly.io/Koyeb/Railway) или домашнем сервере. Держит
   постоянный WebSocket с Discord. Занимается только математикой и записью
   чисел в БД: антиспам-кулдаун на XP за сообщения (не чаще раза в 30 сек),
   учёт войс-времени с защитой от накрутки (время не считается, если юзер
   сидел заглушенным — self_deaf + self_mute). НЕ генерирует картинки и
   НЕ отвечает на слэш-команды.

2. **Cloudflare Worker** (`/worker`, TypeScript) — живёт в сети Cloudflare.
   Просыпается только когда кто-то вызывает команду, и сразу засыпает после
   ответа — не тратит ресурсы простаивая. Достаёт цифры из БД за миллисекунды,
   рендерит карточку через Satori (JSX/HTML/CSS → SVG) и resvg-wasm
   (SVG → PNG), без тяжёлых нативных Linux-библиотек вроде Cairo.

3. **Serverless DB** (Turso/libSQL или Cloudflare D1) — доступна по HTTP API
   из любой точки, оба сервиса читают и пишут в одну базу без сетевых мостов.

## Технические принципы (важно для стиля кода)

- Компактная кодовая база: никаких файлов на тысячи строк. Каждый файл решает
  одну задачу (`collector.ts` ~120 строк, `worker.ts` ~100 строк роутинга,
  `Card.tsx` — визуал карточки).
- Ноль тяжёлых нативных зависимостей — только TypeScript и WASM. Если решение
  тянет за собой нативную сборку (canvas, Cairo и т.п.) — это неверное решение
  для этого проекта, ищи WASM-альтернативу.
- Модульность — задачи решаются независимыми кусками (сначала логика,
  отдельно верстка, потом связка эндпоинтом), чтобы каждую можно было
  реализовать и проверить в одиночку.
- Free-тир как ограничение, а не как временное решение: вся архитектура
  должна укладываться в бесплатные лимиты Cloudflare Workers, Turso и
  контейнера для коллектора — это часть продуктового обещания "0 рублей
  в обслуживании", а не то, что можно нарушить ради удобства.
```

### 0a. Схема БД и структура проекта

```
Создай структуру проекта для Discord level-бота из двух сервисов + общей БД.

Структура:
- /collector — демон-сборщик событий (Node.js или Bun, discord.js v14)
- /worker — Cloudflare Worker (TypeScript, wrangler.toml)
- /shared — общие типы TypeScript, переиспользуемые обоими сервисами

Свяжи пакеты через npm/pnpm workspaces, а не относительными путями. В корневом
package.json:

  {
    "name": "level-edge",
    "private": true,
    "workspaces": ["collector", "worker", "shared"]
  }

Дай /shared своё имя пакета (например "@shared/types" в его package.json) —
тогда и в collector, и в worker можно писать import { calculateLevel } from
'@shared/types' вместо '../../shared/types', даже когда структура папок
разрастётся глубже.

Схема БД (Turso/libSQL, но пиши SQL совместимый и с Cloudflare D1):

Таблица users:
- user_id (text, PK, часть составного ключа)
- guild_id (text, PK, часть составного ключа)
- xp (integer, default 0)
- level (integer, default 0)
- messages_count (integer, default 0)
- voice_seconds (integer, default 0)
- last_message_at (integer, timestamp, для антиспам-кулдауна)
- voice_joined_at (integer, nullable, timestamp начала ТЕКУЩЕГО отрезка войс-сессии —
  не всей сессии целиком, см. пояснение в промпте 0b про сегментный учёт)
- voice_segment_muted (integer/boolean, default 0, был ли self_deaf+self_mute
  активен на момент старта текущего отрезка)

Таблица guild_settings:
- guild_id (text, PK)
- xp_per_message (integer, default 15)
- message_cooldown_seconds (integer, default 30)

Создай миграционный SQL-файл и базовый package.json для обоих сервисов.
Не пиши бизнес-логику пока, только скелет и схему.
```

### 0b. Collector daemon — учёт сообщений и войса

```
В /collector реализуй демон, который держит WebSocket-соединение с Discord
через discord.js (Gateway Intents: GUILDS, GUILD_MESSAGES, GUILD_VOICE_STATES,
GUILD_MEMBERS).

Логика сообщений:
- На событие messageCreate (игнорируя ботов) — проверь last_message_at юзера
  из таблицы users
- Если прошло меньше message_cooldown_seconds (из guild_settings) — только
  инкрементируй messages_count, XP не начисляй
- Если кулдаун прошёл — начисли xp_per_message, обнови last_message_at,
  инкрементируй messages_count
- После начисления XP проверь, не пересёк ли юзер порог левел-апа
  (формула level = floor(0.1 * sqrt(xp)) — можешь предложить свою, но зафиксируй
  её в /shared как отдельную функцию calculateLevel(xp))

Логика войса (событие voiceStateUpdate) — СЕГМЕНТНЫЙ учёт, это важно:

Наивная реализация "проверить self_deaf+self_mute только в момент выхода" —
БАГ: если юзер честно сидел в войсе 3 часа, а перед выходом на 5 секунд включил
заглушение, вся трёхчасовая сессия аннулируется. Вместо этого закрывай отрезок
(и решай, засчитывать его или нет) при КАЖДОЙ смене состояния, не только при
выходе из канала.

Обработай три типа переходов:

1. ВХОД (oldState.channelId === null, newState.channelId !== null):
   - voice_joined_at = now
   - voice_segment_muted = newState.selfDeaf && newState.selfMute

2. СМЕНА MUTE/DEAF-СТАТУСА, юзер остаётся в войсе
   (newState.selfDeaf !== oldState.selfDeaf ИЛИ newState.selfMute !== oldState.selfMute,
   channelId не null до и после):
   - Закрой текущий отрезок: elapsed = now - voice_joined_at
   - Если voice_segment_muted было false — прибавь elapsed к voice_seconds
   - Открой новый отрезок: voice_joined_at = now,
     voice_segment_muted = newState.selfDeaf && newState.selfMute

3. ВЫХОД (oldState.channelId !== null, newState.channelId === null):
   - Закрой отрезок так же, как в пункте 2 (elapsed + проверка voice_segment_muted)
   - Обнули voice_joined_at и voice_segment_muted

Переход между каналами без изменения mute-статуса (channel switch) не закрывает
отрезок — это часть той же сессии, реагируй только на смену канала при null
на входе/выходе и на смену self_deaf/self_mute, больше ни на что.

Держи подключение к БД через @libsql/client. Выведи размер потребляемой памяти
в консоль при старте для проверки (~35 МБ — ориентир).
```

### 0c. Cloudflare Worker — приём interactions и /rank

```
В /worker создай обработчик Discord Interactions Endpoint (POST-запрос от Discord,
с обязательной проверкой подписи через discord-interactions или tweetnacl —
Discord отклоняет endpoint без валидной верификации).

ВАЖНО про тайминг: Discord ждёт первый ответ на interaction максимум 3000 мс.
Поход в БД + скачивание аватарки + рендер через Satori/resvg-wasm вместе легко
могут вылезти за этот лимит, особенно на cold start воркера. Поэтому НЕ пытайся
уложить всю работу в первый ответ — используй deferred-паттерн:

1. Сразу по получении interaction (до похода в БД, до рендера) верни ответ типа 5
   (DEFERRED_CHANNEL_MESSAGE_WITH_SOURCE) — это мгновенно, Discord покажет
   пользователю "Бот думает..."
2. Дальше делай всю работу без спешки — на follow-up через webhook действует
   лимит 15 минут, а не 3 секунды:
   a. Достань из БД строку users по user_id+guild_id (если юзера нет — данные
      для follow-up: эмбед "ещё не начал зарабатывать XP")
   b. Посчитай позицию в топе гильдии по XP (SQL: COUNT юзеров с xp > текущего + 1)
   c. Собери карточку через Satori — JSX-компонент с:
      - Аватаркой юзера (взять avatar URL из interaction.member.user)
      - Цветным кольцом статуса вокруг аватарки (online/idle/dnd — из presence,
        если недоступно — просто нейтральный цвет)
      - Уровнем и позицией в топе, формат "#4 из 1500"
      - Прогресс-баром XP до следующего уровня (неоновый акцентный цвет)
      - Двумя плашками: "💬 Сообщений: {messages_count}" и "🎙 В войсе: {часы}ч"
   d. Скомпилируй JSX → SVG → PNG через resvg-wasm (без Cairo и других
      Linux-нативных зависимостей — только WASM)
3. Отправь результат через PATCH на
   https://discord.com/api/v10/webhooks/{application_id}/{interaction_token}/messages/@original
   с PNG как attachment — это и есть "финальный" ответ, который увидит юзер
   вместо "Бот думает..."

Про шрифты для Satori — ОТДЕЛЬНО ВАЖНО: Satori не рендерит текст без файла шрифта,
но Cloudflare Worker не имеет файловой системы, поэтому fs.readFileSync('font.ttf')
здесь не сработает никогда, даже не пытайся так делать. Шрифт нужно завести как
бинарный модуль через правило в wrangler.toml:

  [[rules]]
  type = "Data"
  globs = ["**/*.ttf"]
  fallthrough = false

и импортировать его как обычный модуль (import fontData from '../assets/font.ttf'),
это даст ArrayBuffer, который напрямую передаётся в опцию fonts у Satori.

Держи весь рендеринг в памяти, никакой записи на диск. Ответ должен укладываться
в разумный CPU-time free-тира, но благодаря deferred-паттерну это уже не вопрос
жизни и смерти для первого ответа.
```
